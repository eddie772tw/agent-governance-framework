# 非同步雲端 Agent (Jules) 委派與驗收流程

## 授權與使用邊界

1. **使用者明確授權**：必須取得維護者明確授權委派；嚴禁僅因任務繁重而擅自外派。
2. **環境與憑證前置**：必須具備合法的 API Client、有效金鑰與已綁定之 Repository。
3. **無憑證邊界**：若無正式連接器，嚴禁假造 API Response、Session 狀態或 PR 成果。
4. **禁止微型任務委派**：小型文檔修復、本地秒級完成之微小改動不應委派，維持通訊效率。

---

## 委派前準備 (Pre-Delegation)

在委派請求中必須明確定義：
- **任務目標與邊界**：清楚定義允許修改之目錄與絕對不可更動之檔案。
- **驗收標準與測試命令**：明確指定必須 100% 通過的測試指令與效能門檻。
- **Ownership 鎖定**：遵守 `cross-agent-collaboration` 規範，委派期間本地 Agent 停止對該目錄之寫入。

---

## 成果回收與本地驗收 (Result Ingestion & Verification)

1. **計畫審查**：若雲端 Agent 回報等待計畫審批 (`AWAITING_PLAN_APPROVAL`)，必須先由人類使用者確認，嚴禁自動代簽。
2. **Diff 與安全性審查**：取得產出之 PR 或 Patch 後，本地檢視 Diff 範圍、套件依賴是否遵守防幻覺查驗協議、是否有安全性弱點。
3. **本地全套重現驗證**：在本地環境完整執行單元測試、靜態分析與 `git diff --check`。
4. **知識庫同步**：若委派過程產生值得沉澱之架構經驗，經本地驗證後提煉記錄至 `.agents/Journal.md`。
