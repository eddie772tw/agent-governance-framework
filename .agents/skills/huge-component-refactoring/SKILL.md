# 巨型元件拆分與高頻熱路徑重構 (Huge Component & Hot-Path Refactoring)

## 何時觸發本技能
1. 單一 UI 組件或程式碼檔案超過 250 行。
2. 單一元件同時承擔數據訂閱、業務計算、內部狀態管理與視圖繪製等多重職責。
3. 修改 60Hz+ 高頻更新、Canvas 渲染、動畫循環或高負載數據串流路徑。

---

## 高頻熱路徑（Hot-Path）效能鐵律

- **零高頻物件分配**：嚴禁在高頻幀循環（如 60FPS）中使用 `.forEach()`、`.map()`、`.filter()`、`Object.keys()`、字串拼接或每幀宣告臨時物件/閉包。
- **記憶體快取與重用**：可重用之數據結構預先配置於 Ref、緩衝區或快取中。
- **快取 DOM / 樣式查詢**：嚴禁每幀重複查詢 DOM 元素或頻繁讀寫 CSS 自訂屬性，避免觸發瀏覽器強制重排 (Reflow)。
- **資源與訂閱清理**：元件卸載 (Unmount / Cleanup) 時必須嚴格清理 WebSocket、Timer、Worker、Event Listener 與 Observer，防止記憶體洩漏與重複訂閱。

---

## 250 行巨型元件重構步驟

1. **鎖定檔案並建立測試基線**：
   - 記錄 Ownership，執行既有測試確保目前行為正確無誤。
2. **抽離純計算邏輯**：
   - 將元件內的資料轉換、格式化與演算法抽至獨立純函數工具模組，並建立單元測試。
3. **語意化子元件拆分**：
   - 將龐大的視圖子樹（DOM Tree）依功能拆分為獨立子組件（例如精靈嚮導的多步驟介面拆為獨立 Step 組件）。
   - 僅透過 Props 傳遞必要資料，嚴禁透傳包含全域狀態的巨型物件。
4. **狀態機與 Hook 抽離**：
   - 將複雜的表單驗證、非同步請求與多步驟狀態收攏至自訂 Hook 或狀態機中。
5. **驗證與回歸測試**：
   - 執行單元測試、E2E 測試與靜態檢查，確認畫面渲染與互動行為零偏差。
